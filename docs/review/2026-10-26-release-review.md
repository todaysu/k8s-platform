# FTC 集群运维平台 v1.1.0 发布审核

## 审核结论

v1.1.0 通过代码单测、竞态检测、静态检查、前端生产构建和生产依赖审计，未发现已知的发布阻断缺陷。代码已实现面向 60+ 集群的有界并发、快照读路径、角色隔离、分片租约和失败保护。但发布等级为“候选生产版”：现有 100 集群数据是短时模拟，尚不能替代 60 真实集群长稳和故障注入验收。

## 代码和调用链审核

- 多集群概览、容量、事件和搜索主路径读取平台数据库，没有页面请求对 60 套集群做无界同步扇出。
- 节点、Pod、日志、工作负载、监控和终端是单集群按需路径，受每进程和跨副本配额保护。
- Event 问题概览在 MySQL 中使用集合聚合，避免每集群 2N 查询。
- 安全扫描和报告是持久化后台任务，不会长时占用 API 请求。
- 资源索引仅在完整批次成功后替换，失败不发布部分数据。
- 所有状态修改路由均需显式 RBAC 声明，终端 WebSocket 启用 Origin 校验。

## 本次修正

- 消除报告模型连接测试中的未使用局部变量警告。
- 将告警时间筛选处理从未使用表达式改为明确分支，避免 lint 噪声和后续维护误判。
- 统一发布版本为 v1.1.0，同步 Makefile、Dockerfile、安装清单、前端包元数据和文档。

## 非阻断风险

| 风险 | 影响 | 处理建议 |
| --- | --- | --- |
| 主前端 JS 约 1.32 MB，gzip 约 367 KB | 低带宽首次加载较慢 | 下一版按一级页面懒加载，分离 PatternFly 大组件 |
| lint 仍有历史 purity hooks 和转义警告 | 暂未破坏功能，会降低新问题可见度 | 建立警告基线并逐页清零 |
| SPA 通用响应的 CSP HSTS X-Frame-Options 不完整 | 防御深度不足，但 Cookie、Origin、RBAC 已实施 | 由交付入口先开启 HSTS frame 和 CSP，再回归终端与报告 iframe |
| 资源索引仍为全量成功批次替换 | 大集群首次索引写放大 | 基于真实数据库锁和 IO 结果决定是否引入 UID 增量 |

## 尚未完成的生产容量验收

1. 60 套真实或等效独立集群运行 24 小时，10 个独立浏览器用户执行混合流程。
2. 10% 集群离线、高 RTT、证书错误和 API 429 时无重试风暴。
3. Event 突发、Watch 410、队列恢复和数据缺口可见性。
4. 独立 Pod 级 API Collector Worker kill、网络分区和 shard 接管。
5. MySQL 慢查询、短时不可用、连接耗尽、备份和恢复演练。
6. 十个终端长连接、大日志输出、大 Prometheus 序列和同集群监控竞争。

## 发布准入条件

- 用本次生成的镜像 SHA-256 完成离线导入验证。
- 使用生产 MySQL 演练安装、升级和回滚。
- 核对所有目标集群 RBAC，确认高权限工具仅向管理员开放。
- 完成上述 60 集群容量验收后，才将支持范围正式标记为 60+。
