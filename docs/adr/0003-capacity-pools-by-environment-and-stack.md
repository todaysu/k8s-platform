# ADR-0003：按环境、集群类型与技术栈划分容量资源池

- 日期：2026-10-18
- 状态：已接受

## 背景

同一环境可能同时存在 G01 和 OCP 两类集群，其中 G01 又分为 TCS 和 CMBK8S 技术栈。不同环境之间不能调度，G01 与 OCP、TCS 与 CMBK8S 也可能具有不同的平台固定开销、资源规格和部署约束。将这些集群的可分配容量直接相加，会让一个资源池的余量掩盖另一个资源池的容量风险。

## 决策

以“环境 × 集群类型 × 技术栈”作为容量计算的最小资源池边界。例如 STP/G01/TCS、STP/G01/CMBK8S 和 STP/OCP 分别汇总集群 Allocatable、平台 Requests、业务 Requests、未分类 Requests、待调度 Requests 与安全预留。

字段约束为：G01 只能搭配 TCS 或 CMBK8S，OCP 只能搭配 OCP。历史数据按技术栈自动迁移：TCS/CMBK8S 归入 G01，OCP 归入 OCP。

全局概览只展示资源池数量、各资源池中的最低 CPU/内存余量和需关注资源池数量，不展示跨资源池累加后的可调度余量。容量详情必须先选中一个资源池，再展示该池的分布、风险和集群明细。

## 后果

### 正面

- 不同环境、集群类型和技术栈之间不再互相抵消容量风险。
- 运维人员可以直接定位 STP/G01/TCS 等具体资源池。
- 后续应用调度容量判断可以复用相同资源池键。

### 负面

- 页面增加一层资源池选择，需要用户先确认计算范围。
- 集群的环境、集群类型或技术栈标记错误会导致容量进入错误资源池。

### 中性

- 单集群容量计算公式保持不变，仅改变多集群聚合边界。

## 备选方案

- 全部集群直接汇总：界面简单，但会产生不可调度的“虚假余量”，不采用。
- 只按环境划分：无法体现同一环境内不同技术栈的平台开销和部署约束，不采用。
- 每个集群独立查看：准确但缺少资源池层面的整体判断，不采用。
