# 跨集群事件排查 Implementation Plan

**Goal:** 实现异常类别 → 影响对象 → UID 校验的实时证据与日志入口，并将原始事件改为可分页的次级检索。

**Architecture:** 保留 List+Watch 和现有持久化模型。按有索引的时间范围分批/流式读取匹配 Event，在服务端完整聚合类别与对象，只向浏览器返回当前页；不再基于 500 条采样计算总量。事件来源与原始累计次数保持可追溯。实时检查按需读取单个对象，不批量扫描集群，失败标记未知。

**Tech Stack:** Go、client-go、SQLite/MySQL、React/PatternFly。

## Steps
1. 扩展 FleetEventQuery/Overview 和对象实时证据模型，新增类别函数、完整分页聚合与业务清单过滤；保留未知异常的原始指纹，Normal 仅在检索中显式开启。
2. SQLite/MySQL 增加流式扫描能力和对象 UID/名称筛选；仓库测试覆盖分页大于 500 条、同名不同 UID、业务/平台总量一致、不同诊断原文保留。
3. 新增对象按需核验接口，核验对象 UID、ownerReference/ReplicaSet 链，返回容器状态/退出信息/日志可用性；删除、替换、API 不可用不误报恢复。
4. 页面重构为异常排查与事件检索两个入口，保留筛选和页码，按类别下钻影响对象，再下钻当前状态与关联事件。原始消息折叠，分页和明确累计次数。
5. Go 与前端回归测试、构建、lint、真实集群只读验证、浏览器验证与截图；重启本地后端保留现有配置。

不引入自动根因结论、自动修复、额外集群 Agent 或工单状态；保留资源 UID 和完整错误消息，不将不同仓库错误混成已确认的同一根因。

## 实施结果（2026-10-19）

- 完成服务端完整聚合、类别/对象/原始记录分页、统一业务清单过滤，以及 SQLite/MySQL 流式查询；不再将 500 条采样作为全量统计。
- 完成按资源 UID 的实时核验、真实 ReplicaSet → Deployment 归属链、独立 Pod、已删除/替换/未核验状态；容器退出与上次退出信息保留。
- 完成默认异常排查、独立检索、可展开证据、按对象 UID 的 Normal 前后文、可扩大时间范围，以及当前/上次容器日志入口。
- 后端全量测试通过；28 项前端测试通过；构建、lint 通过。覆盖 654 条异常记录、超过 12 个未知类别、分页、归属筛选、Normal 前后文、替换资源和部分数据缺失。
- 真实集群验证镜像拉取异常影响对象、具体代理拒绝连接证据、Deployment 所属链，以及 myapp 中现存独立 Pod 的正常状态。没有为了验证创建额外故障或修改业务清单。
- 本地后端已保留原配置重启。剩余边界：全量索引范围采用流式服务端聚合而非额外缓存；超过查询时限明确报错，不冒充完整结果。未知资源类型保留历史证据，不猜测当前状态。

## 事件检索按资源合并（2026-10-19）

事件检索使用服务端 resources 视图，按集群、资源类型、Namespace、UID 聚合并分页；UID 缺失时退回名称并明确提示。同一对象不同 Reason/类型归为一行，展示最新消息、事件记录数和累计发生次数之和。同名重建资源保留独立行。展开按原筛选时间范围及相同 UID 分页读取原始事件，保留当前筛选与包含 Normal 设置；核验对象入口继续可用。

验证：后端全量测试通过；前端 29 项测试、构建、lint 通过。新增覆盖同一 UID 多事件合并、Normal 合并、重建 UID 分开、展开查询保留原时间范围。

## 工作负载归并补充

事件检索及影响对象列表按可核验的 controllerReferences 合并：Pod → ReplicaSet → Deployment；StatefulSet、DaemonSet、Job 等使用直接控制器。批量读取 Pod / ReplicaSet，按 UID 关联，聚合在分页前完成，保留各 Pod 的事件数、累计计数、完整证据及单 Pod 核验入口。集群、Namespace 和控制器 UID 不同的对象仍隔离。独立 Pod 单列。

边界：历史事件未保存 ownerReferences。已删除或无法读取控制器归属的 Pod 保持单列，不按名称截断猜测。ReplicaSet 无权读取时保留可核验的直接控制器归并。

工作负载归并验证完成：后端全量测试通过；前端 30 项测试、构建、lint 通过。修复空事件结果导致展开失败，展开资源时暂停自动刷新。实测 nginx-deployment 三个现存 Pod 的 12 条事件合并展示，展开可分别查看各 Pod 原始事件。
