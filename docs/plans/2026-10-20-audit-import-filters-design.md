# 审计日志导入后过滤设计

## 目标

导入 1–5 个 Kubernetes Audit JSON Lines 文件后，运维人员先对全部请求进行过滤，回答“某个来源 IP 或操作人做了什么”；随后再选择资源，查看该资源及其关联资源链。

## 参考模式

- Kubernetes Audit Event 使用结构化字段记录 `sourceIPs`、`user`、`verb`、`responseStatus`。
- OpenSearch Dashboards Discover 采用“字段 + 操作符/值”的离散过滤器。第一版数据量有限，因此使用更直观的字段下拉框，选项从当前数据动态生成。

## 第一版范围

1. 来源 IP：精确匹配 `sourceIPs` 数组中的任一值。
2. 操作人：精确匹配 `user.username`。
3. 动作：默认显示全部动作，避免从 Source IP 反查时漏掉 get/list/watch；可切换仅变更操作或单一 verb。
4. 结果：成功、失败、结果未记录。
5. 时间线显示来源 IP；证据视图保留经过安全投影的 `sourceIPs`。
6. 请求过滤位于资源选择之前，过滤后直接展示匹配请求，并同步缩小可下钻的资源列表。
7. 选择请求过滤条件时退出单资源视图，回到全局匹配结果；点击结果中的资源再进入关联链。

## 安全与边界

- 不保留完整 `requestURI`，避免查询参数中的敏感信息进入浏览器状态。
- 不保留请求正文、Secret、环境变量和 Token。
- 页面过滤只处理已经导入浏览器的数据，不重新读取节点文件；大文件仍应先使用“生成导出命令”缩小范围。
