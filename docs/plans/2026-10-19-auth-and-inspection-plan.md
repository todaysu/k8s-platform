# 登录权限与巡检分析

参考 Red Hat ACM 的角色权限模型，并简化为全平台三种角色：admin 管理配置与账号、operator 查看及 Pod Exec、viewer 只读。使用本地账号、bcrypt、服务端随机会话、HttpOnly/SameSite Cookie、登录限速、同源操作检查。所有业务 API 强制登录，所有写入仅 admin，Exec 仅 admin/operator。管理员账号来自现有环境配置，不内置默认密码；新增账号持久化，禁用/角色或密码修改后撤销已有会话。前端登录门禁、退出、账号管理和角色说明，保留 API 权限为最终边界。

实施：认证存储及中间件 → 接入服务 → 登录与账号管理 UI → 权限提示 → 测试和本地验证。

巡检分析当前仅规划：手动启动只读检查，按集群连接、节点健康、工作负载可用性、Pod 异常、容量余量和基线漂移形成报告。报告记录检查时间、范围、规则版本、未能检查项、证据与资源链接。结果区分严重/警告/正常/未知；归并按工作负载 UID，保留具体 Pod。第一阶段不自动修改集群，不用历史事件直接判定当前故障。后续加入定时计划与报告对比，AI 只辅助解释已有证据。

## 完成情况

登录权限已实现并接入本地服务。支持初始化管理员、登录/退出、当前用户、账号创建、角色修改、禁用、密码重置、自助修改密码。数据库保存账号和 bcrypt 哈希，Cookie 仅保存随机会话标识，服务端保存其 SHA-256。拒绝越权写操作及只读用户的终端请求，前端配置入口同时按角色禁用。管理员不能禁用自己或自行降权。未认证 API 401、跨源操作 403、登录限速 429。

当前本地旧密码哈希为占位值，已进入一次性初始化流程。凭证文件为 data/bootstrap-token，用户在页面自行输入凭证并设置密码；不提供默认密码。

验证：后端全量测试、认证模块 race 检查通过；前端 34 项测试、构建、lint 通过。浏览器验证初始化页面，实际代理登录请求正确进入认证校验，未登录集群 API 返回 401。修复认证初始化与采集启动之间的 SQLite 写锁竞争，认证迁移先完成再启动采集，并配置写等待。巡检模块本轮仅设计，导航保持后续标识。
