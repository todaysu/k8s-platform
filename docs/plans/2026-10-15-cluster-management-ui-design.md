# 集群管理页面 UI 设计

> 日期：2026-10-15
>
> 状态：UI 原型已实现，待产品评审

## 1. 目标

为轻量化 Kubernetes 多集群运维平台建立第一个可评审的管理页面，验证约 60 套集群规模下的信息密度、筛选方式、状态表达和纳管入口。

本阶段只实现前端 UI 和本地交互，不接入数据库、真实 Kubernetes API 或 Prometheus。

## 2. 部署边界

平台最终作为 Web 服务部署到 Kubernetes，通过 Deployment、Service 和 Ingress 对外提供访问。不开发桌面端，不要求用户单独下载或运行客户端二进制文件。

生产镜像可同时包含 Go 服务和编译后的前端静态资源，对外表现为一个平台服务。

## 3. 页面结构

### 3.1 左侧导航

- 健康概览。
- 集群管理，当前选中。
- 业务全景，标记为后续能力。
- 事件中心，标记为后续能力。
- 巡检分析，标记为后续能力。
- 系统设置和单管理员身份。

### 3.2 页面标题区

- 页面标题与功能说明。
- “UI 原型数据”标记，防止模拟数据被误认为真实状态。
- 刷新状态按钮。
- 添加集群按钮。

### 3.3 汇总区

- 已纳管集群。
- 连接正常。
- 需要关注。
- 连接失败。

汇总卡片使用左侧状态色条，避免大面积状态色造成视觉干扰。

### 3.4 筛选区

- 按集群名称或 API Server 搜索。
- 按 DEV、PRD 环境筛选。
- 按运行正常、需要关注、连接失败筛选。
- 显示总集群数与当前结果数。

### 3.5 集群表格

表格列包括：

- 集群名称和 API Server。
- DEV/PRD 环境。
- 连接状态。
- Kubernetes 版本。
- Ready 节点数与节点总数。
- Ready 实例数与实例总数。
- 异常数量。
- 最后检查时间。
- 更多操作入口。

点击集群行打开右侧详情栏，展示连接地址、版本、节点、实例、Warning Event 和异常原因。后续可从详情栏进入完整集群详情页面。

## 4. 添加集群弹窗

第一版只录入：

- 集群名称。
- Kubeconfig。

Kubeconfig 支持：

- 上传文件。
- 粘贴内容。
- 自动使用 `current-context`。
- 点击“纳管集群”后完成连接验证与安全保存，不设置第二次确认。

弹窗明确提示 Token 不会展示，原始 Kubeconfig 不会长期保存。

## 5. 视觉原则

- 采用工业运维风格，强调信息密度和状态识别。
- 深色控制栏用于导航，浅色数据区用于长时间查看。
- 正常、警告和失败同时使用颜色、文字和图标表达。
- PRD 使用深色环境标签，但不与错误状态混用。
- 页面背景使用低对比度网格，形成控制平面的视觉语义。
- 窄屏隐藏固定侧栏，统计卡片自动纵向排列，表格允许横向滚动。

## 6. 当前原型交互

- 搜索集群。
- 环境筛选。
- 状态筛选。
- 打开和关闭添加集群弹窗。
- 上传与粘贴录入方式切换。
- 集群名称或 Kubeconfig 为空时禁用“纳管集群”。
- 点击集群行查看详情侧栏。

所有交互均使用模拟数据，不会执行真实集群操作。

## 7. 后续评审重点

1. “需要关注”和“连接失败”的状态命名是否符合运维习惯。
2. 列表是否需要增加机房、区域或凭据过期信息。
3. DEV/PRD 是录入字段、命名规则推导，还是集群标签读取。
4. 汇总区是否保留在集群管理页，还是只放在健康概览主页。
5. 单步纳管失败时的错误提示是否足够清晰。
6. 右侧详情栏需要保留哪些快捷操作。
