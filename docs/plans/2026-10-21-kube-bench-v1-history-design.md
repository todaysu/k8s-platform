# kube-bench 安全扫描 V1 设计

## 决策

安全扫描第一版只提供 kube-bench CIS 扫描。平台为目标集群每个节点创建临时高权限 Job，通过 hostPID、UID 0 和只读 hostPath 读取节点配置；不再提供快速 API 检查和 Kubescape。扫描结束后读取 JSON 日志、聚合为集群报告并自动回收 Job。

## 数据与历史

保留现有 `security_baseline_results` 作为每套集群的最新任务状态，确保多集群台账查询固定为每集群一行。新增 `security_baseline_history` 追加保存每次最终结果，包括失败任务。集群详情按需读取最近 20 次历史，避免主页随 60+ 集群历史增长而变重。旧的最终结果在迁移时按 `(cluster_id, started_at)` 去重导入历史表。

差异只比较最近两次成功扫描，以 `control_id` 为稳定键：本次由 PASS/不存在变成 FAIL/WARN 为新增风险；由 FAIL/WARN 变成 PASS/不存在为已修复；两次都存在风险但状态发生变化为状态变化。节点样例变化不单独制造新控制项，完整证据仍在报告中查看。

## 页面

“安全扫描”位于“运维工具”之后。手动扫描弹窗只负责选择集群并明确提示高权限范围。集群详情先展示本次摘要，再展示与上次成功扫描的变化，随后是历史选择和控制项报告。平台不自动整改。

## 约束

V1 执行器保持单副本；平台重启会终止旧任务、保存失败历史并清理残留资源。OCP 需要专用 SCC。无法访问的托管控制面必须标记为未覆盖，不能视为通过。
