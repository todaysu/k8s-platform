# 跨集群事件中心实施计划

## 目标

在现有非侵入式 Kubernetes Event List+Watch、MySQL/SQLite 持久化和单集群事件页之上，增加一个全局事件中心。运维人员可按环境、技术栈、集群、事件类型和资源对象筛选，在一个页面识别影响多个集群的重复问题，并下钻到单集群事件或资源详情。

## 范围与设计取舍

- 复用中心端采集器，不在被纳管集群安装 Agent。
- 复用 `cluster_events` 和 30 天保留策略，不引入新的存储组件。
- 后端提供全局查询接口，避免前端逐集群发起请求。
- 第一版使用稳定的事件指纹（类型、原因、对象类型、归一化消息）归并问题；保留原始事件列表用于核对。
- 采集失败与业务告警分开显示，避免把平台无法采集误判为集群健康。
- 页面沿用现有 ACM/PatternFly 风格：指标卡、筛选工具栏、问题列表、原始事件下钻。

## 实施步骤

1. 扩展领域模型和事件仓库接口，支持指定集群集合的全局事件查询与采集状态读取。
2. 在 MySQL 与 SQLite 实现带 `cluster_id IN (...)` 的时间范围、类型、对象和关键字过滤，并保持现有索引可用。
3. 增加服务层全局事件概览：按环境/技术栈/集群过滤，补充集群元数据，生成事件指纹和问题归并摘要。
4. 增加 `/api/v1/events` 全局接口及参数校验。
5. 增加前端 API 类型与跨集群事件页面，启用左侧导航入口，并实现筛选、归并列表、原始事件列表和下钻。
6. 补充单元/页面测试，执行 Go 测试、前端测试、Lint、构建与差异检查。
7. 在浏览器中验证桌面布局、空状态、错误状态和交互。

## 验收标准

- 可从左侧“跨集群事件”进入 `/events`。
- 页面默认展示最近 24 小时事件，并可按环境、技术栈、集群、类型、对象类型和关键字筛选。
- 同类事件可跨集群归并，显示发生次数、影响集群数、对象数和最近发生时间。
- 能查看原始事件，并从 Pod、工作负载、Node 事件进入对应集群资源页面。
- 页面显示每个纳管集群的采集状态；部分集群失败不影响其他集群的数据展示。
- MySQL 与 SQLite 行为一致，既有单集群事件接口不回归。
