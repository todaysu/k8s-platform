## 大文件 audit

目标：同一集群 3–5 个 master 文件，单文件约 500 MB（合计约 1.5–2.5 GB 原始文件），可混入该集群的轮转文件。首期 JSONL/.log/.jsonl 和 .gz，不支持 tar/zip。现有 20 MiB 浏览器解析保留为轻量模式，不直接放大上限。

采用“导入任务”：创建任务绑定集群、时区/来源 master 标签、文件清单；分块上传、校验、重试/断点续传，进入异步队列，列表显示各文件已传字节、已解析行、异常行、当前阶段、取消/删除及过期时间。不能把上传百分比当整体分析进度。限制任务并发与每用户配额，上传/任务查询/删除都校验拥有者和角色；管理员不默认向其他用户开放内容。

后端流式读取/解压，按字节分块组装 JSON 行；限制总展开字节、压缩比、单条大小、磁盘剩余与任务时间，超限显式失败/提示，不静默丢弃。采用有界通道与批量事务，避免整个文件或全体请求驻留内存。初期每任务 SQLite 文件，单写入者批量入库，索引覆盖时间、namespace/resource/name/UID、auditID、code、ownerUID；需要时增加 FTS，不先引入 Elasticsearch/Kafka。

同一任务中的重传文件按校验值识别，同一 auditID 各阶段合并，文件/master 来源列表保留；重复阶段记录比较内容，不把差异静默丢弃。多个 master 的文件不是必然重复，也不是天然完整。多文件索引完成后按 owner UID 建立关联，不能只保留导入筛选资源而漏掉关联子资源。按时间排序但不声称消除 master 时钟偏差，缺失审计时间段/阶段/策略覆盖限制在报告中展示。

解析前的原始分块临时文件设私有目录，避免凭据进入普通服务日志；解析后默认仅保留安全投影与关联字段，及时删除原始分块，完成/失败/取消都有回收路径。任务数据有可配置 TTL、配额、手动删除和启动后恢复清理机制。若未来提供完整原始证据留存，单独授权、加密与保留策略，不能无提示落盘。

结果 API：任务状态、资源搜索、请求分页、资源摘要/时间线、单条证据。浏览器只持有当前页和小摘要。先用合成 500 MB ×5 文件进行吞吐、峰值内存、磁盘增长、取消、重启、损坏 JSON、重复/乱序阶段、跨文件 owner、gzip 异常和用户隔离验收，再确定默认容量限制。

## 监控信息架构

监控是一级大类：默认进入多集群概览，选择集群后进入 Grafana 风格的固定看板。以原生看板为主，统一时间选择、刷新、变量、图例和资源钻取；已有 Grafana 可提供带时间与变量的外链，首期不做 iframe 单点登录或可视化看板编辑器。

1. 多集群概览：各集群数据源状态、采集完整度、异常数、关键资源当前值/迷你趋势，不叠加所有集群所有曲线。异常独立呈现，不阻塞其他集群。
2. 集群总览：节点 Ready、CPU/内存使用与 requests/limits、Pod/工作负载状态及时间趋势。
3. 节点：CPU/内存/磁盘/网络、压力与节点上的异常 Pod。
4. 工作负载：namespace → Deployment/StatefulSet/DaemonSet/Pod，副本、重启、CPU/内存、节流与 OOM 指标（有数据时）。业务范围复用全局业务 namespace 配置，按资源 owner 关联，不重复配置业务分类。
5. 集群组件：API Server 延迟/错误率/请求量、etcd 延迟/容量、scheduler 队列与调度时延、controller-manager、CoreDNS、CNI/CSI（各组件实际可采集才显示）。不能将 API Server 导出的 etcd 客户端指标当成 etcd 服务端完整指标。
6. 业务指标：QPS、错误率、P95/P99 和依赖，只在业务应用/网关 exporter 已暴露且配置了指标映射时展示；资源 Ready/容器 CPU 不能替代应用请求指标。

统一顶部：集群、namespace、workload/节点、最近 1h/6h/24h/7d/自定义、刷新间隔。图表选择时间窗口可带同一集群/资源/时间跳至事件与审计排障；不要自动把监控时间选择当成审计数据已存在。

## 数据层与采集补齐

每集群显式绑定数据源：支持独立 Prometheus，或共享 Prometheus/Thanos/VictoriaMetrics 查询入口。共享入口需不可歧义的 cluster_id 标签映射；后端强制加入集群作用域与权限，不能只依赖前端筛选。数据源凭据仅后端保存，不把任意 URL 作为查询参数。Kubernetes API proxy 可兼容已有轻量查询，高频 range queries 优先走可控后端数据源连接。

新增能力检测：连接、指标查询、采集 targets、关键指标族与标签、最近样本和请求时间范围覆盖。无权限、未部署、采集失败、指标不存在、数据过期、超出保留期分别呈现。不把无数据画为零，不把 targets up 当业务健康。

按需补齐：cAdvisor/kubelet 用于容器资源；node-exporter 用于主机资源；kube-state-metrics 用于对象状态；API Server/etcd/scheduler/controller-manager/CoreDNS 指标端点与 scrape/RBAC/TLS；应用/网关埋点或 exporter 用于业务 SLI。先盘点并复用现有采集，不在各集群盲目安装全套组件。

后端 query/query_range 网关按预置面板模板查询，缓存、取消、超时、并发和序列上限，长时间范围提高 step，每条曲线目标约 300–600 个点（设计目标，待验证）。面板进入视口后加载，切换集群取消旧请求，全局只查摘要。多副本采集需选定来源/明确去重，避免 HA 与多 endpoint 双重计算；不直接平均跨集群百分比。

## 开发顺序

两条工作线独立交付：
- 审计：任务/分块上传/权限 → 流式解析与索引 → 多文件关联/分页 API → 任务与排障 UI → 2.5 GB 基准及恢复/回收测试。
- 监控：数据源管理与能力检测 → test01 补齐采集并验证指标 → query_range 与集群总览 → 节点/工作负载 → 组件 → 业务指标映射。将已验证的数据源配置推广至其他集群。

不以安装组件代替用户确认具体部署范围；本次为规划，不部署新监控组件。
