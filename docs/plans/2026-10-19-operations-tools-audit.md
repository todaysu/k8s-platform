# 运维工具与审计日志分析

## 实现

- 独立一级菜单“运维工具”，路由 /tools；通过 tools/catalog.ts 注册工具的名称、描述和入口。
- 审计工具 /tools/audit：本地导入 Kubernetes audit JSON Lines，20 MiB 上限，Worker 解析，清除数据与取消旧导入；不上传日志或写浏览器持久化存储。
- 导入摘要包含有效事件数、合并请求数、资源身份数、失败请求、错误行和覆盖时间。支持来源集群标签或离线分析；单文件须来自一个集群。
- 按 auditID 合并阶段，保留最高完成阶段的状态，按时间排序审计阶段和请求；按 namespace/resource/name/UID 区分资源。
- 按真实 owner UID 追踪子资源，包括创建失败没有自身 UID、但请求中有 ownerReferences 的子资源。不按 Pod 名称或控制器名称前缀猜测。
- 默认展示变更请求，可切换关联子资源、读取请求、失败请求。时间线展示操作者、记录镜像与副本、返回码、原因，25 条分页。
- 展开证据展示字段白名单投影，不保留请求正文、Secret 内容、URL 查询、环境变量或任意 annotations。Metadata 或没有请求/响应对象时不伪造配置差异；API 成功不代表部署 Ready。
- 内置虚构示例日志，明确提示示例不是实际集群。
- “监控”是独立一级菜单 /monitoring，目前展示已有多集群当前指标、连接状态与最近检查时间，点击集群进入详情。无历史曲线，断连或无指标时不显示零值或旧的百分比为有效指标。

## 验证

解析测试覆盖乱序阶段、无效行、不同 UID 同名资源、敏感正文过滤、没有自身 UID 的失败子资源关联；组件测试覆盖工具入口、文件导入、资源选择、失败请求与清除数据。前端全套测试、构建、lint；浏览器用隔离预览页面验证真实 Worker 解析示例、Deployment/ReplicaSet/Pod 关联、失败过滤与证据展开。截图 data/kind-test/audit-analysis.png，使用虚构示例数据。临时预览页面已删除。

## 范围

第一期不提供服务端日志存储、实时采集、压缩包、多集群混合文件或通用插件上传执行。后续 Pod 临时调试容器可注册在同一工具目录。监控历史查询需后续接入 Prometheus range query。
