# FTC 集群运维平台页面说明

## 文档目的

本文档按 ACM 风格的“总览到资源钻取”方式说明每个页面的用途、数据源、主要操作和数据边界。所有跨集群数字都应同时解读采集时间与覆盖状态。

## 一级页面

| 页面 | 解决的问题 | 主要数据源 | 关键操作 |
| --- | --- | --- | --- |
| 健康总览 | 哪些集群或资源需要先处理 | 健康快照、告警快照、容量快照 | 按状态钻取集群、进入告警或巡检 |
| 集群管理 | 纳管、分类、查找和移除集群 | 集群登记与健康快照 | 新增、验证 kubeconfig、编辑环境和技术栈 |
| 指标监控 | 查看某个集群或节点的时序表现 | 目标集群 Prometheus | 选集群、时间范围、节点和面板组 |
| 告警中心 | 当前有哪些告警，哪些已恢复 | Alertmanager 采集与历史库 | 按级别、集群、命名空间、持续时间筛选，打开资源 |
| 资源容量 | 资源池的供给、业务使用、平台开销和容量缺口 | 容量快照与分类规则 | 按环境、G01 OCP、技术栈过滤，钻取集群 |
| 事件检索 | 跨集群识别高频故障和证据 | Event 原始记录、日聚合 | 问题视图、对象视图、证据时间线和资源钻取 |
| 主动巡检 | 把健康、容量、Event 转换为可执行问题 | 已保存的多集群数据 | 按严重级和集群处理问题，跳转证据 |
| 运维报告 | 生成周、月、季的稳定性报告 | Event 聚合、告警、快照、安全扫描 | 选周期和资源池、启动后台任务、打开 HTML 报告 |
| 安全基线 | 手动检查 CIS 与 Kubernetes 资源安全风险 | kube-bench Job 与只读 API 检查 | 最多 2 集群并行扫描、对比最近两次、加入白名单 |
| 运维工具 | 在明确目标上执行高权限排障 | 单集群实时 API Exec 和工具包库 | kubectl、Pod 终端、Arthas、HTTP 文件服务 |
| 平台管理 | 管理用户、角色、参数和 AI 报告模型 | 平台数据库 | 账号管理、参数修改、重启生效、模型连接测试 |

## 集群详情页

| 标签 | 内容 | 数据特性 |
| --- | --- | --- |
| 概览 | 节点、实例、核心组件、API 延迟和最近采集时间 | 默认读快照，显式刷新才实时访问 |
| 节点 | Ready 状态、角色、版本、CPU 和内存 | 按需实时访问 |
| 工作负载 | Deployment StatefulSet DaemonSet 及 Pod | 按需实时访问，支持 owner 钻取 |
| Pod 详情 | 容器状态、重启、日志与终端 | 实时、受 RBAC 和会话配额保护 |
| 容量 | 单集群供给、使用、命名空间分类和基线 | 默认快照，基线决策需管理员 |
| Event | 单集群 Event 列表、摘要和筛选 | 平台持久化数据，不是 Kubernetes Event 完整审计日志 |

## 空数据和失败数据

- “0”表示成功采集且数值为零。
- “—”、“采集不可用”或“等待首次采集”表示不能做出零值结论。
- 告警、Event 和监控是不同证据源；名称相关只是排障线索，不代表已确认为同一故障。
- 过期快照仍保留最后成功值，但不应用于声明当前实时状态。
