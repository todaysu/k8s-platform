# FTC 集群运维平台使用手册

## 快速开始

1. 访问交付人员提供的 HTTPS 地址，使用平台账号登录。
2. 先查看“健康总览”，确认采集覆盖和最近刷新时间。
3. 按“连接失败 → 紧急告警 → 节点和实例不健康 → 容量高水位”顺序处理。
4. 从问题卡或告警打开资源，再查看 Event、日志和监控，保留完整证据链。

## 纳管集群

1. 以管理员进入“集群管理”，选择“添加集群”。
2. 输入唯一名称、环境、资源池、技术栈和 kubeconfig。
3. 先执行连接验证，检查 API Server、版本、权限和基础发现结果。
4. 确认后纳管。新集群需等待首次健康、容量、告警和索引采集，期间不应解读为零资源。
5. 若需移除，先确认历史报告与事件保留要求，再执行移除。

## 日常巡检

- 健康总览：确认总集群数、连接状态、API P95 和资源 Ready 比例。
- 告警中心：先看 Critical，再按持续时间和重复次数排序；展开采集覆盖，排除数据缺口。
- 主动巡检：处理具有直接资源链接的问题，不仅根据汇总数字判断。
- 资源容量：按环境和资源池查看 CPU、内存、Pod 槽位及平台开销。
- 事件检索：查看最近 24 小时高频 Warning，展开具体 Pod 证据。
- 指标监控：只对已定位的集群和节点查看趋势，避免同时打开大量面板。

## 故障排查流程

1. 在告警或巡检中确认集群、命名空间、Kind 和对象名称。
2. 打开工作负载或 Pod 详情，检查 owner、容器状态和重启。
3. 用 Event 时间线判断是调度、镜像、探针、资源或存储问题。
4. 查看同一时间窗口的指标和日志。
5. 只在读取证据不足时启动 Pod 终端、kubectl 或 Arthas，并保持最小操作范围。

## 生成运维报告

1. 管理员进入“运维报告”，选择自然周、月或季。
2. 选择环境和 G01 OCP 资源池；空选择表示全部纳管范围。
3. 启动生成后可离开页面，Worker 在后台执行。
4. 完成后在报告记录中打开独立 HTML。模型失败不会丢失事实图表，但必须注意 AI 未完成提示。

## 安全扫描

1. 选择少量集群开始，确认 kube-bench 镜像在目标架构上可用。
2. 扫描期间平台会在目标集群创建临时 Job，结束后回收。
3. 优先查看新增风险和未整改项，再确认已整改项。
4. 仅当风险经审核确认可接受时加入白名单，必须填写原因。

## 角色边界

| 角色 | 典型能力 |
| --- | --- |
| 管理员 | 纳管集群、容量基线、安全扫描、kubectl、Arthas、报告生成、用户和参数管理 |
| 运维员 | 查看全部运维数据、日志和普通 Pod 终端 |
| 只读用户 | 查看集群、资源、容量、告警、Event 和报告 |

## 操作原则

- 看到 429 时等待页面重试，不要快速重复点击。
- 对离线集群先处理网络、证书或凭据，不要通过提高并发规避。
- 对实时页面优先收窄集群、节点和时间范围。
- 所有快照和报告都有时间边界，进行故障定责时应保留原始日志和监控证据。
